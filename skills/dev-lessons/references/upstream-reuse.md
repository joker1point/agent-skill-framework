### U-01 复用不复制：逐行复刻 = 双份 bug 维护
- 场景：#上游同步 #架构
- 问题：本地 v2.0 后端从上游 v1.6 逐行复制纯函数，上游更新 bug fix 后本地静默漂移，同一 bug 要修两遍。
- 根因：复制代码而非动态引用。
- 方案：建 `backend/upstream_shim/` 适配层，用 `importlib.util.spec_from_file_location` 动态加载上游纯函数；依赖本地 schema 的函数保留 v2.0 适配版。
- 反模式：直接 `import` 上游模块（schema 冲突、缺依赖、无 `__init__.py` 全会炸）。
- 溯源：2026-07-06_upstream_shim_design.md

### U-02 namespace 隔离 + stub 注入 + 三级 fallback
- 场景：#Python #动态加载
- 问题：第一版 shim 用本地模块名加载上游代码，`sys.modules` 被覆盖；上游 module-level import 缺依赖直接失败。
- 根因：namespace 污染 + 依赖链断裂。
- 方案（shim 标准四步）：
  1. **独占 namespace**：模块名用 `_tmp_upstream_*` 前缀，绝不与本地重名；
  2. **stub 注入**：加载前把上游缺失的依赖以 no-op stub 塞进 `sys.modules`；
  3. **纯函数边界**：只 shim 纯函数；有状态/DB 依赖的保留本地实现；
  4. **三级 fallback + 等价性测试**：上游加载失败 → 本地副本 → 报错；fallback 路径要有等价性测试兜底。
- 溯源：2026-07-06_upstream_v16_shim.md

### U-03 看到惊艳的参考产品，先分清"效果呈现"与"产出机制"再估复用成本
- 场景：#参考项目 #复用评估 #设计决策
- 问题：拿着一个文章排版产品的 Showcase（每篇都被夸"编辑级"）来问"能给自己的博客做同样的优化吗"——直觉是"它有一套好主题，套过来即可"。
- 根因：核实其仓库与文档后确认：Showcase 效果 = **每篇文章单独用 AI 定制生成的单文件产物**（主题契约 + 逐篇生成管线），**不是**一套可套用的 CSS 主题。能复制的不是效果本身，而是**方法论**：编辑级结构（eyebrow 元信息 / 导语 / 编号章节 / 目录）+ 语义组件语汇 + token 化设计系统。
- 方案：把复用目标从"复制效果"换成"借鉴方法论"，落到站点自身技术栈上实现（本次 = 文章页结构重做 + prose 精修 + 语义组件库，零外部依赖）。
- 反模式：按 Showcase 观感估复用成本（"找它的主题包就行了"）；把对方的产品形态（AI 逐篇生成）误当样式方案；因为"效果复制不了"就整体放弃借鉴。
- 溯源：TechLog 文章页改版（2026-09-28；Reacticle / garden-skills 评估结论）

### U-04 对接第三方插件/扩展系统：协议以"官方插件源码"为准，别信文档概要
- 场景：#第三方集成 #协议逆向 #桌面集成
- 问题：按第三方插件开发文档写出的卡片，按钮"看着正常、点了没反应"。文档只写了"组件 emits close/action"，没给参数形态；另外官方卡片还有两处文档未提的惯例（自带关闭按钮、非常驻时画自动隐藏进度条），一并漏掉。
- 根因：事件载荷形态靠猜——传了 `{id}` 对象，而官方约定是**裸字符串 id**；文档概要 ≠ 实现契约。
- 方案：对接第三方扩展系统时，**拿官方示例插件的源码逐行对照**（本次两个官方插件各十行代码就定死协议）；把确认后的契约（载荷形态、事件名、宿主注入的全局对象、子进程 stdin/stdout JSONL 通信方式与各消息字段）写进自己项目的交接文档，供后来者直接照抄。
- 反模式：拿"文档里提到过"当实现细节；猜完 API 形态不第一时间对照官方实现，而是继续往上叠功能。
- 溯源：Catrace flowwatch-alert 插件（2026-09-19 会话）
